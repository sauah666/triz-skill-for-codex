# Security Policy

This repository is meant to stay public-safe.

## What should not be in the repo

- secrets, tokens, keys, or real credentials
- private customer or partner data
- internal-only URLs or instructions
- copyrighted source text copied from the original PDFs

## If you find a problem

- Do not open a public issue with sensitive payloads.
- If GitHub private advisories are available, use them.
- Otherwise open the smallest possible issue that names the file and the category of problem, without pasting secrets or private data.

## Common report types

- leaked credential
- license or provenance mismatch
- private/internal reference that should not be public
- sample data that reveals real people or organizations
